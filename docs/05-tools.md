# Инструменты

## Что это

Обслуживание панели: выгрузка проекта, обновление, очистка лога и кэшей.

## Логика работы

1. Вкладка «Управление проектом» выгружает архив и сбрасывает настройки.
2. Вкладка «Обновление» проверяет GitHub и устанавливает новую версию.
3. Вкладки «Управление логом» и «Управление кэшем» очищают данные.
4. Опасные действия просят подтверждение и пишутся в «Журнал событий».

## Управление проектом

### Экспорт проекта

Скачивание архива проекта. Три варианта:

- **Чистый проект** — только структура файлов, без логов и настроек.
- **С настройками** — вместе с конфигом и списком пользователей, без логов.
- **Полный бэкап** — всё, включая лог-файлы.

Выгрузка пишется в «Журнал событий» и может вызывать уведомление «Выгружен проект (резервная копия панели)». В архив с настройками попадают пароли в виде хешей: храните его как секретный.

### Сбросить настройки

Возвращает настройки к значениям по умолчанию (тема, язык, группы, устройства). Действие необратимо, поэтому панель просит подтверждение. Событие «Сброшена конфигурация панели» имеет высокую важность в уведомлениях.

## Обновление

- **Блок сведений:** репозиторий (`AlexandreKz/Monitor-VLMCSD`), ветка, текущая версия, время последней проверки, статус.
- **Кнопки:** «Проверить обновления», «Обновить проект» (открывает окно подтверждения со списком файлов, затем «Да, обновить»), «Проверить GitHub» (проверка доступа и сертификата).
- **Тип обновления** (два канала):
  - «Релиз (стабильный)» — файлы из тега последнего опубликованного релиза;
  - «Ранний доступ (по SHA)» — файлы из ветки `main`; обновлением считаются новые и изменённые файлы.
- **Токен GitHub (необязательно):** повышает лимит запросов к GitHub с 60 до 5000 в час. Хранится в зашифрованном виде.
- **Автоматически проверять обновления (оба канала):** флажок «Включить автопроверку» и выбор интервала в часах.
- **Автоматическое обновление** — в разработке (пункт 62 бэклога).
- **Как идёт установка:** файлы скачиваются во временную папку и сверяются с репозиторием по SHA, затем делается резервная копия заменяемых файлов (в `backups/update_…` папки данных) и файлы заменяются. Если что-то пошло не так, выполняется откат. Папки `pic/` и `screen/`, настройки и данные панели не обновляются, файлы, которых нет в репозитории, не удаляются.
- **Проверка по расписанию:** `update_check.php` завершается с кодом 0 (обновлений нет), 10 (есть обновление) или 1 (ошибка проверки). Для него в cron можно добавить `0 */6 * * * www-data php /var/www/html/vlmcconf/update_check.php >/dev/null 2>&1`.
- Если вы вносили в файлы панели собственные правки, ранний доступ предложит заменить их версией из репозитория: сначала загрузите свои правки в репозиторий.
- **Консоль** внизу показывает ход проверки и установки.
- Если проверка сертификатов не проходит, раздел показывает подсказку «Как подключить проверку сертификатов».

События «Доступна новая версия панели», «Панель обновлена», «Ошибка обновления панели» подписываются в «Уведомления».

## Управление логом

- Блок сведений: файл лога, размер, статус, дата первого события.
- **Очистка по датам:** поля «С» и «По» и кнопка «Очистить».
- **Полная очистка:** флажок «Очистить всё», флажок «Резервная копия» (сначала сохранить копию) и кнопка «Полная очистка».
- Очистка лога необратима, поэтому сначала сделайте резервную копию. Действие пишется в «Журнал событий», есть событие уведомления «Очищен лог KMS-сервера».

## Управление кэшем

- **Кэш геолокации:** число файлов и объём кэша; кнопки «Очистить кэш», «Обновить кэш» (заново запросить данные для всех IP из лога, может занять время: окно предупреждает об этом) и «Проверить» (статистика кэша).
- **Кэш эмодзи:** статус кэша, «Очистить кэш» (удалить файл) и «Обновить кэш» (загрузить актуальный список эмодзи из интернета).

## Важно

- Сброс настроек и очистка лога необратимы: перед ними сделайте «Полный бэкап».
- В архиве «С настройками» лежат хеши паролей: храните его как секретный.
- Не запускайте обновление, пока не сделали резервную копию: при сбое панель откатит файлы, но данные лучше сохранить заранее.

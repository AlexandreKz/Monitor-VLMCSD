# Безопасность

## Что это

Учётные записи и права пользователей, защита входа и ограничение доступа к панели по IP.

## Логика работы

1. Администратор создаёт пользователей и задаёт им права по разделам.
2. Вход защищён требованиями к паролю, таймаутом и ограничением неудачных попыток.
3. Дополнительно доступ к панели можно ограничить списком адресов и скрыть IP на главной странице от неавторизованных.
4. Все изменения пишутся в «Журнал событий».

## Вкладка «Пользователи»

### Управление пользователями

Таблица: логин, роль (набор прав по разделам), дата создания, действия. Текущий пользователь помечен «Текущий».

- **Добавить пользователя:** логин, пароль и права по разделам.
- **✎** — изменить права пользователя. **🔑** — сменить пароль. **✕** — удалить пользователя.
- Права по разделам показаны значками. Для большинства разделов три уровня: нет доступа 🚫, просмотр 👁️, редактирование ✏️. Для белых IP и уведомлений два состояния: ✅ и ❌. Что открывает каждое право, описано в [«Права пользователей»](12-permissions.md).
- Пользователь, у которого есть все права, считается полным администратором. Только он видит раздел «API».
- Изменения пользователей пишутся в «Журнал событий» (пароли и токены туда не попадают).

### Требования к паролю

Минимум 8 символов, заглавные и строчные буквы, цифры и спецсимволы. При первом входе под `root`/`root` панель требует сменить пароль.

### Таймаут входа

Через сколько минут без действий вход завершается: от 5 до 1440 (24 часа), по умолчанию 30. Применяется сразу, уже вошедшие пользователи продолжают работу с новым значением.

### Скрытие IP-адресов

Настройка «Скрывать IP-адреса от неавторизованных». При включении главная страница без входа показывает размытые заглушки вместо адресов в логе и в списке «Неизвестные устройства». Реальные адреса в страницу не передаются. Блок «Подозрительные IP» остаётся открытым. Менять может только администратор.

### Не подозрительные (белые IP)

Адреса из списка «Не подозрительные» не попадают в блок «Подозрительные IP» на главной. Добавить адрес можно кнопкой «➕ Добавить IP» (поле «IP-адрес» и комментарий) или с главной страницы. Нужно право «IP Whitelist: управление».

## Вкладка «Доступ и IP»

### Белый список IP для панели

Переключатель «Открывать панель управления только с указанных адресов». Когда он включён, страницы панели и вход открываются только с адресов и сетей из списка (и с самого сервера). Остальные получают ошибку 403 со страницей, на которой видно их адрес. Главная страница с логом и API не затрагиваются.

- Показывается «Ваш адрес». Кнопка «📍 Добавить мой адрес» вносит его в список, чтобы не закрыть себе доступ.
- Список «Разрешённые адреса и сети»: адрес или сеть (IPv4 и IPv6, формат CIDR) и комментарий.
- Панель не даст сохранить настройку так, чтобы вы потеряли доступ сами.
- Отказы пишутся в «Журнал событий» (адрес, страница, браузер; не чаще раза в 10 минут на адрес).
- Адрес определяется по соединению (`REMOTE_ADDR`). За обратным прокси (nginx, Cloudflare) все посетители видны с адреса прокси, поэтому там ограничение лучше задавать на самом прокси.

### Аварийное отключение

Если вы закрыли себе доступ, на сервере создайте пустой файл `panel_whitelist.off` в папке данных (команда `touch` показана в панели) или задайте переменную окружения `VLMC_PANEL_WHITELIST_OFF=1`. Ограничение сразу перестанет действовать. После правки списка файл нужно удалить вручную (команда `rm` тоже показана).

## Вкладка «Firewall»

Функция блокировки IP из блока «Подозрительные IP» находится в разработке: вкладка закрыта пометкой «В разработке», в «Информация → Статус» строка Firewall показывает «В разработке».

В коде уже есть: выбор механизма (ufw, nftables, iptables), область блокировки (все порты или только порт панели), список заблокированных адресов, кнопки «Применить неприменённые» и «Применить все заново». Веб-серверу нельзя менять правила фаервола напрямую, поэтому нужен скрипт-помощник и правило sudo; подробности и причина паузы описаны в пункте 30 бэклога.

## Важно

- Не закрывайте себе доступ: перед включением «Открывать панель управления только с указанных адресов» добавьте свой адрес кнопкой «📍 Добавить мой адрес». Если всё же закрыли, снимите ограничение файлом `panel_whitelist.off`.
- Первый вход под `root`/`root` требует смены пароля: не оставляйте стандартный пароль.
- За обратным прокси (nginx, Cloudflare) все посетители видны с адреса прокси: ограничение по IP задавайте на самом прокси.
